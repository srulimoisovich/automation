# Лабораторная работа №2. Получение курса валют через Web API

## Цель работы

Научиться писать на Python скрипт, который обращается к Web API, обрабатывает полученный ответ, сохраняет данные в файл и корректно сообщает об ошибках.

## Задание

Написать скрипт `currency_exchange_rate.py`, который:

1. принимает из командной строки исходную валюту, целевую валюту и дату;
2. запрашивает у сервиса курс валют на эту дату;
3. сохраняет полученные данные в формате JSON в каталог `data/` (имя файла содержит обе валюты и дату, каталог создаётся, если его нет);
4. обрабатывает ошибки (неверные параметры, ошибка API, отсутствие связи, некорректный ответ): выводит понятное сообщение в консоль и записывает его в файл `error.log`;
5. проверен на нескольких датах (не менее 5) из периода 2025-01-01 — 2025-09-15, взятых через равные промежутки.

## Используемые технологии

| Технология | Для чего используется |
|---|---|
| Python 3 | язык, на котором написан скрипт |
| `requests` | отправка HTTP-запроса к сервису и получение ответа |
| `argparse` | разбор параметров командной строки (`-f`, `-t`, `-d`, `-k`, `-u`) |
| `logging` | запись ошибок в файл `error.log` с датой и временем |
| `json` | сохранение результата в файл |
| `datetime` | проверка даты и отметка времени сохранения |
| `os`, `sys` | пути к файлам, поток ошибок, код возврата |

Библиотека `requests` выбрана потому, что с ней запрос записывается одной строкой: параметры строки адреса передаются в `params`, тело POST-запроса в `data`, а время ожидания в `timeout`. Модуль `logging` сам добавляет к каждой строке журнала дату, время и уровень сообщения.

## Как работает скрипт

Шаги совпадают с комментариями `# Шаг N` в функции `main()`.

1. **Настройка журнала.** `setup_logging()` подключает `logging` к файлу `error.log` рядом со скриптом. В журнал пишутся только ошибки.
2. **Чтение параметров.** `read_arguments()` разбирает командную строку через `argparse`. Если не указан обязательный параметр, `argparse` сам выводит подсказку и завершает программу с кодом 2.
3. **Проверка валют.** `check_currency()` проверяет, что код состоит ровно из трёх латинских букв ASCII, и переводит его в верхний регистр.
4. **Проверка даты.** `check_date()` разбирает дату по шаблону `%Y-%m-%d` и проверяет, что она лежит в пределах 2025-01-01 — 2025-09-15. Зачем она нужна, видно на примере: если отправить сервису дату 2025-12-01, он ответит с пустым полем `error` и курсом 0.2599766021058105, хотя данных за декабрь у него нет. Отличить такой ответ от настоящего нельзя, поэтому скрипт проверяет диапазон сам, ещё до запроса.
5. **Запрос к сервису.** `request_rate()` отправляет `POST {url}/?from=...&to=...&date=...`, ключ передаётся в теле запроса (`key=...`). Время ожидания ограничено 10 секундами. Затем проверяются HTTP-код, то, что ответ является JSON, поле `error` и наличие поля `data`.
6. **Сохранение.** `save_to_json()` создаёт каталог `data/` (если его нет) и записывает в файл параметры запроса, ответ сервиса и время сохранения.
7. **Вывод результата.** `main()` печатает курс и путь к сохранённому файлу и возвращает код 0.

Если на любом шаге 3–6 возникает ошибка, функция вызывает `report_error()` и возвращает `None`, а `main()` возвращает код 1. Исключения наружу не выбрасываются.

## Структура скрипта

Константы в начале файла:

| Константа | Значение |
|---|---|
| `API_URL` | адрес сервиса по умолчанию, `http://localhost:8080` |
| `API_KEY_ENV` | имя переменной окружения с ключом, `EXCHANGE_API_KEY` |
| `DEFAULT_KEY` | ключ по умолчанию, `EXAMPLE_API_KEY` |
| `FIRST_DATE`, `LAST_DATE` | границы доступного периода |
| `REQUEST_TIMEOUT` | время ожидания ответа, 10 секунд |
| `SCRIPT_DIR` | каталог скрипта, получен из `__file__` |
| `DATA_DIR`, `LOG_FILE` | `SCRIPT_DIR/data` и `SCRIPT_DIR/error.log` |

Функции:

| Функция | Назначение | Принимает | Возвращает |
|---|---|---|---|
| `setup_logging()` | настраивает запись ошибок в `error.log` | — | `None` |
| `report_error(message)` | печатает сообщение в stderr и пишет его в журнал | текст ошибки | `None` |
| `read_arguments()` | разбирает параметры командной строки | `sys.argv` | `argparse.Namespace` |
| `check_currency(code)` | проверяет код валюты и переводит в верхний регистр | код валюты | код или `None` |
| `check_date(date_text)` | проверяет формат и диапазон даты | дата | дата `ГГГГ-ММ-ДД` или `None` |
| `request_rate(currency_from, currency_to, date_text, api_key, api_url)` | выполняет запрос и проверяет ответ | валюты, дата, ключ, адрес | ответ сервиса (`dict`) или `None` |
| `make_file_name(currency_from, currency_to, date_text)` | составляет имя файла | валюты, дата | строка `RON_to_MDL_2025-01-10.json` |
| `save_to_json(currency_from, currency_to, date_text, response_data)` | создаёт `data/` и записывает файл | валюты, дата, ответ | путь к файлу или `None` |
| `main()` | выполняет шаги 1–7 | — | код возврата 0 или 1 |

У каждой функции есть docstring на русском языке с разделами `Аргументы:` и `Возвращает:`.

## Формат сохраняемых данных

Имя файла: `<ИЗ>_to_<В>_<ГГГГ-ММ-ДД>.json`, например `data/RON_to_MDL_2025-01-10.json`.

Содержимое файла (реальный файл из тестового запуска):

```json
{
    "request": {
        "from": "RON",
        "to": "MDL",
        "date": "2025-01-10"
    },
    "response": {
        "error": "",
        "data": {
            "from": "RON",
            "to": "MDL",
            "rate": 0.25861846018568807,
            "date": "2025-01-10"
        }
    },
    "saved_at": "2026-10-23 15:30:14"
}
```

- `request` — параметры, которые отправил скрипт;
- `response` — ответ сервиса без изменений;
- `saved_at` — дата и время сохранения файла.

Обратите внимание: ключ, с которым выполнялся запрос, в сохранённый JSON не попадает, его там нет ни в `request`, ни в `response`.

## Обработка ошибок

Все сообщения выводятся в stderr, дописываются в `error.log`, а скрипт завершается с кодом 1.

| Ситуация | Сообщение в консоли | Запись в `error.log` |
|---|---|---|
| код валюты не из трёх латинских букв | `Ошибка: код валюты должен состоять из трёх латинских букв (получено: "RO").` | то же сообщение |
| дата в неверном формате | `Ошибка: дата "10.01.2025" указана в неверном формате, ожидается ГГГГ-ММ-ДД.` | то же сообщение |
| дата вне периода | `Ошибка: дата 2025-09-16 выходит за пределы доступного периода (2025-01-01 — 2025-09-15).` | то же сообщение |
| сервис не запущен | `Ошибка: не удалось подключиться к сервису http://localhost:8089. Проверьте, что он запущен.` | то же сообщение |
| сервис не ответил вовремя | `Ошибка: сервис http://localhost:8080 не ответил за 10 секунд.` | то же сообщение |
| HTTP-код не 200 | `Ошибка: сервис вернул HTTP-код 500 (...)` | то же сообщение |
| ответ не JSON | `Ошибка: сервис вернул ответ, который не является JSON (...)` | то же сообщение |
| непустое поле `error` | `Ошибка API: Invalid API key (запрос RON -> MDL, 2025-01-10)` | то же сообщение |
| нет поля `data` | `Ошибка: в ответе сервиса нет данных о курсе (...)` | то же сообщение |

Строка журнала имеет вид `ГГГГ-ММ-ДД ЧЧ:ММ:СС - ERROR - текст`.

## Выводы

В ходе работы был написан скрипт на Python, который получает курс валют у Web API на заданную дату и сохраняет результат в JSON-файл. Параметры передаются через `argparse` с короткими и длинными ключами, запрос выполняется библиотекой `requests` с ограничением времени ожидания, ошибки выводятся в консоль и записываются в `error.log` через `logging`.

Тестирование на семи датах с шагом 40 дней показало, что курс RON → MDL в данных сервиса держится в пределах примерно 0.255–0.263. Проверки на стороне скрипта оказались необходимы: на дату вне периода сервис отвечает курсом без всякой ошибки, а на дату в неверном формате присылает HTML вместо JSON при неверном формате даты, поэтому дата проверяется до отправки запроса. Пути к `data/` и `error.log` считаются от расположения скрипта, поэтому результат не зависит от каталога, из которого запущен скрипт.
